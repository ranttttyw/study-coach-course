# 学习教练 Agent 中文实战教程

> 适合已经学过 Python、模型 API 和 Agent 基础的学员。先用零密钥演示模式跑通，再接真实模型，最后围绕 Memory、上下文工程和工具调用做改造。

本项目是基于开源 Study Coach 的独立教学改编包，不是从零原创的软件。原始代码、许可证、来源与修订说明见 `upstream_original/`、`LICENSE`、`NOTICE.md`。本教程、课堂图和实验说明为新增编写；Hello-Agents 仅作为知识点对照与课前阅读链接，不随包复制其教材正文、图片或实现。

## 当前 MVP 新增能力

- **本地账号登录：** 首次使用请注册用户名和至少八位密码。应用只使用服务端生成的账号 ID 读取档案、测验和教材，不再让前端输入学习者编号。密码以 scrypt 哈希保存；这是本地教学环境的最小登录实现，公网部署前应接入经验证的身份服务、HTTPS、限流和密码重置流程。
- **测验草稿恢复：** 出题后会立即写入数据库。刷新或重新打开应用后会恢复同一套题目；已评分题目不能重复评分。
- **教材 PDF / PPTX：** 在“教材资料”页上传文字型 `.pdf` 或 `.pptx`，系统会提取可复制文字并按账号、学习目标隔离保存，自动识别章节。在进度问答中，模型可检索命中页并显示文件名和页码。扫描版 PDF、图片和复杂图表尚未解析；扫描 PDF 请先 OCR。

新增依赖已写入 `pyproject.toml` 和 `uv.lock`。更新代码后先运行 `uv sync --frozen`，再执行 `uv run --frozen streamlit run app.py`。

## 1 项目到底解决什么问题

学习者往往记了很多笔记，却不清楚自己是否理解，也很难把过去的反馈带到下一次练习。这个应用把一次学习过程分成五步：

1. 保存目标、周期、每周学习时间和偏好。
2. 输入今天学习的主题和笔记。
3. 生成三到五道简答题，并要求学员用自己的话复述。
4. 学员提交答案后，模型针对**同一份原题**给出反馈。
5. 保存记录，让进度助手按需读取档案与历史，再讨论下一步。

建议课堂场景：学员 A 想在四周内掌握 Agent 的记忆设计，偏好代码练习。今天学习“工作记忆与长期记忆”，完成练习后询问“我最近应该优先复习什么”。讲师可以打开工具证据和数据库，让学员看到信息从哪里来。

### 1.1 学完应能解释的事

- 为何“聊天窗口里有记录”不等于应用已经有长期记忆。
- 为何用户档案应从数据库确定性读取，而不是让模型猜一个。
- 为何测验必须绑定题目快照，不能在评分时重新生成题目。
- 固定工作流和模型自主选择工具的单 Agent 有何差异。
- 如何限制历史、工具结果和调用轮数，避免无限增长。
- 如何用可执行测试验证工程性质，用人工标注集验证模型质量。

### 1.2 当前没有实现的能力

课程版没有教材上传、Embedding、向量检索、自动周计划、真实登录、多人权限、后台复习提醒，也没有参数微调训练。档案页“计划周期”只是保存字段，不代表已经生成日历计划。可以按第12节逐步扩展，展示和简历中应区分已实现与计划实现。

## 2 原版与课程版的边界

| 维度 | 原始版本 | 本包默认课程入口 |
|---|---|---|
| 界面 | 英文 Streamlit | 中文 Streamlit，增加记忆检查 |
| 工作流 | 出题和评分串联，提交时再次走全图 | 按阶段分流，出题与评分各自结束 |
| 评分题目 | 可能在提交后重新生成 | 固定题目快照和编号 |
| 长期记忆 | Memori v3 与外部 SQL 数据库 | SQLite 显式档案和学习事件 |
| 档案恢复 | 语义检索失败后可能调用模型重建 | 按学习者编号直接查询记录 |
| 进度对话 | 经 Memori 注册的模型调用 | 三个只读工具与有上限的单 Agent 循环 |
| 模型配置 | 多处写死模型名 | 服务端集中配置 |
| 无密钥使用 | 不能正常完成初始化 | 演示模式可完整验证流程 |
| 多人边界 | 固定 entity_id 等需要进一步检查 | SQL 按编号过滤，但编号不是身份认证 |
| RAG | 没有教材检索管线 | 未加入，作为进阶实验 |

**为什么更换默认记忆后端：**课程第一阶段要让学员先看清读写边界、题目状态和工具执行。显式 SQL 存储易于检查，不需要额外记忆服务或云数据库。原版 Memori 代码完整保留，作为后续“框架式记忆 vs 显式记忆”的比较材料。本课程版不声称已经验证原版 Memori 云端闭环。

两个关键修复是基于原版代码审查：原图有 `generate_quiz → evaluate` 的固定边，`run_evaluation` 配置没有被节点读取；`run_full_evaluation` 又从出题节点进入。修订后 `stage` 存在图状态中，条件边明确选择生成或评分，评分函数必须接收已生成的 `quiz`。

## 3 准备环境与解压

### 3.1 所需环境

- 推荐 Python 3.12；课程声明支持 3.11 到 3.13，但本包实际验证环境见 `docs/VERIFICATION.md`。
- 一个文本编辑器，例如 VS Code。
- 终端、浏览器、可以下载 Python 依赖的网络。
- 推荐使用 uv；也提供纯 pip 路线。
- 演示模式不需要 API Key。安装依赖仍然需要联网，“演示离线”指运行时不调用模型 API。

无需 Docker、VM、独立 Agent Runtime、向量数据库或 Memori 账号。这里的普通 Python 运行环境与专门的 Agent Runtime 平台不是一回事。

### 3.2 解压位置

把 ZIP 解压到自己有写入权限的位置，例如桌面下 `study-coach-course`。打开这个文件夹，确认能同时看见 `app.py`、`pyproject.toml`、`uv.lock` 和本 README。

不要直接在 ZIP 预览器里运行。也不要一开始进入 `upstream_original/`，那是保留的原版研究材料。

建议路径不要太深。终端提示“找不到 app.py”时，先检查当前目录是否正确。

## 4 第一条路线 零密钥启动

以下两种安装方式二选一。不要先用全局 pip 安装，再在另一个 uv 环境启动。

### 4.1 推荐 uv 路线

先按照 [uv 官方安装说明](https://docs.astral.sh/uv/getting-started/installation/) 安装 uv，然后在项目根目录执行：

```bash
uv --version
uv python install 3.12
uv sync --frozen --python 3.12
```

预期：项目中出现 `.venv`，依赖安装结束，没有 `error`。`--frozen` 使用随包的锁文件，不重新求解依赖。如果 Python 已安装且希望减少下载，可直接 `uv sync --frozen --python 3.12`。

macOS 或 Linux：

```bash
cp .env.example .env
uv run --frozen python scripts/doctor.py
uv run --frozen streamlit run app.py
```

Windows PowerShell：

```powershell
Copy-Item .env.example .env
uv run --frozen python scripts/doctor.py
uv run --frozen streamlit run app.py
```

打开终端显示的本地地址，通常为 `http://localhost:8501`。诊断命令只打印密钥是否已配置，不输出密钥值。

### 4.2 不使用 uv 的 pip 路线

macOS 或 Linux：

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
python scripts/doctor.py
python -m streamlit run app.py
```

Windows PowerShell，不需要修改脚本执行策略：

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.venv\Scripts\python.exe scripts/doctor.py
.venv\Scripts\python.exe -m streamlit run app.py
```

`requirements.txt` 是从课程版锁文件导出的固定依赖。Python 的 `sqlite3`、`json` 等标准库不需要另装。若编辑器报红，选择项目 `.venv` 中的 Python 解释器。

### 4.3 演示模式的验收点

页面顶部明确显示“离线流程演示”。完成档案、生成题目、提交答案后：

- 有三道围绕主题的模板题。
- 有已收到答案的流程反馈。
- **没有真实模型分数**，也不应把它解释为对知识水平的评价。
- “记忆检查”能看到保存的档案和事件。
- 进度问答按固定顺序执行三个工具，并展示结果；它不是模型自主路由的验证。

运行演示模式时不应调用外部模型。首次 uv 启动若环境尚未同步，仍可能检查或安装依赖。

### 4.4 停止和再次启动

在启动服务的终端按 `Ctrl+C`。再次运行相同启动命令，使用相同学习者编号；已经落盘的档案和记录仍然存在。

刷新浏览器通常会重新建立 Streamlit 会话，因此当前未提交题目可能丢失。已写入 SQLite 的档案和学习事件不依赖浏览器会话。根目录的 `data/` 是运行时生成的数据，不在交付 ZIP 中。

## 5 第二条路线 接入真实模型

### 5.1 编辑服务端配置

在 `.env` 中将模式改为在线并填入你自己的服务参数：

```dotenv
COACH_MODE=online
OPENAI_API_KEY=填写你自己的密钥
OPENAI_BASE_URL=
COACH_MODEL=gpt-4o-mini
COACH_DB_PATH=data/study_coach.db
COACH_RECENT_LIMIT=6
COACH_MAX_TOOL_STEPS=4
```

`OPENAI_BASE_URL` 留空时，SDK 使用默认服务地址。其他兼容服务需填写其文档要求的接口根地址，常见形式以 `/v1` 结尾。模型名称填你账号中实际可用的名称，不要照抄截图中的展示名。此包没有针对某一个第三方供应商完成真实调用测试。

### 5.2 需要模型支持哪些能力

| 能力 | 在哪里使用 | 不支持时的表现 |
|---|---|---|
| Chat Completions 风格接口 | 模型适配层 | 404、接口路径不匹配 |
| JSON Object 输出 | 出题和评分 | 400、输出不是合法 JSON |
| 函数工具调用 | 进度问答 | 不接受 `tools` 或不能选择工具 |
| `tool_choice` 的 required / auto | 首轮确保读取事实，后续自行选择 | 兼容接口拒绝参数 |
| 多轮工具结果回传 | 读取记忆后形成回答 | 模型忽略结果或协议报错 |

不要把“可调用聊天接口”当成“全部 Agent 能力都兼容”。先通过出题检查，再单独完成一次评分和进度工具调用。

### 5.3 在线配置检查

停止原服务后，在项目根目录执行：

```bash
uv run --frozen python scripts/doctor.py --online
```

这一步会发起真实模型请求，可能产生费用。通过后，表示网络、密钥、指定模型和本例 JSON 出题链路可用；**不表示**评分质量、所有工具调用或 Memori 都已验证。

再启动：

```bash
uv run --frozen streamlit run app.py
```

修改 `.env` 后建议完整停止并重启服务。已在进程中的同名环境变量优先于 `.env`；部署平台 Secrets 又优先于环境变量。配置不生效时，先查是否同时设置了多个来源。

### 5.4 模型调用发生在哪里

- 保存档案：只写数据库，不调用模型。
- 生成测验：通常一次模型请求。
- 评分：通常一次模型请求，使用原题。
- 进度问答：一次或多次模型请求，由工具循环决定。
- SDK 某些失败可能重试一次，所以供应商侧请求数不一定等于点击数。

`COACH_MAX_TOOL_STEPS=4` 限制进度助手的模型回合数，每回合最多接受六个工具调用。达到上限时返回停止信息，不继续后台运行。

## 6 跟着做一遍完整演示

### 6.1 保存学习档案

在侧栏保持编号 `learner-001`，进入“学习档案”：

| 字段 | 示例 |
|---|---|
| 昵称 | 学员A |
| 学习目标 | 四周内掌握单 Agent 的记忆设计 |
| 计划周期 | 四周 |
| 每周小时 | 6 |
| 学习主题 | Memory，上下文工程，LangGraph |
| 偏好形式 | 代码练习，图解 |

点击保存，切换到“记忆检查”，确认 JSON 与表单一致。刷新后应能从数据库读回。当前表单只维护明确填写的档案，不会自动推断未填写的信息。

### 6.2 生成并回答本次题目

进入“学习与测验”，填写主题“工作记忆与长期记忆”，学习30分钟，形式选择代码练习，笔记写“知道二者的存储位置，但还不清楚刷新后保留什么”。点击生成。

记住页面的题目编号，并观察三到五道题。逐题作答，填写复述后提交。评分应针对页面上的这份题目，而不是产生另一份题目。在线分数是模型建议，不是标准化测验结果。

### 6.3 观察写入的学习事件

在“记忆检查”确认出现一条记录。在线记录有建议分数，演示记录的分数为空。点击导出，检查 JSON 中的：

- `attempt_id`：本次题目提交编号。
- `topic`：主题。
- `payload.result.quiz`：评分所依据的题目快照。
- `payload.answers` 与 `payload.explanation`：答案和复述。
- `model` 与 `prompt_version`：复现实验所需信息。
- `is_demo`：是否为模拟流程数据。

同一学习者和题目编号重复写入只保留一条记录。若评分成功但数据库写入失败，可以重试；重试可能再次调用模型，应注意费用。本版没有跨进程队列或分布式幂等执行器。

### 6.4 让进度助手读取记忆

可以依次问：

1. “我的目标和偏好是什么？”
2. “我最近学了哪些主题？”
3. “哪些主题需要优先复习？请说明依据。”

在线模式首轮要求模型使用工具，再由模型选择后续工具或回答。打开“本次工具调用和证据”，检查它调用了哪个函数、读到了什么，而不只看文字是否流畅。

只有一条记录时，合理结论应很有限。模型不应声称已经掌握你的长期规律，也不能从少量数据得出“看视频一定比练习更有效”。演示模式只显示固定说明与真实数据库证据。

### 6.5 验证编号过滤

将编号改为 `learner-002`，其档案和历史应为空。切回原编号后应恢复原数据。这验证的是数据查询过滤。知道另一个编号的人仍可切换到该编号，所以它不是安全的用户隔离方案，不能直接对公网多人开放。

### 6.6 验证数据管理

导出当前用户数据，检查内容，再勾选确认并删除。当前用户数据应清空，其他编号的数据不应被删除。删除动作只清本地应用表，不会删除模型供应商可能保留的请求日志。

## 7 读懂项目结构和执行路径

| 文件 | 职责 | 建议阅读顺序 |
|---|---|---|
| `config.py` | 配置来源、模式、数据库路径、数量边界 | 1 |
| `study_graph.py` | 数据模型、阶段路由、出题与评分 | 2 |
| `memory_utils.py` | 档案和学习事件的确定性读写 | 3 |
| `coach_agent.py` | 三个只读工具及单 Agent 循环 | 4 |
| `llm_gateway.py` | 演示/真实模型适配、JSON解析 | 5 |
| `app.py` | 页面、表单、题目快照和会话状态 | 6 |
| `tests/test_course.py` | 回归测试与模拟工具协议测试 | 7 |
| `scripts/doctor.py` | 配置与连接诊断 | 按需 |
| `uv.lock` / `requirements.txt` | 可复现依赖 | 不手工改版本号 |
| `upstream_original/` | 指定提交的原始代码快照 | 对照阅读 |
| `docs/` | 架构、优化实验、验证记录、课堂讲义 | 按需 |

### 7.1 一次出题的调用路径

`app.py` 收集表单 → `LearnerProfile / StudyLog` 校验 → `run_initial_verification` → 状态设置 `stage=generate` → 条件边选择生成节点 → `CoachModel.ask_json` → `QuizOutput` 校验 → 返回题目 → UI 保存题目编号和快照。

评分时从 `stage=evaluate` 进入，只把当前快照、答案和复述传给评分节点。该图本身没有暂停恢复服务。人工填写答案发生在两次独立图调用之间，由 UI 保存中间状态，不要将其说成 LangGraph 的 checkpoint / interrupt 已实现。

### 7.2 为什么使用 Pydantic

模型输出文本存在变形风险。`QuizOutput` 限定题数和结构；`GradeOutput` 限定0到100的分数、反馈和下一步建议。非法输出应失败并提示检查，不应把无法解析的文字当成有效分数保存。

### 7.3 什么是工具循环

在进度问答中，模型可以请求 `get_profile`、`get_recent_sessions` 或 `get_topic_stats`。Python 根据白名单执行对应函数，再把结果以工具消息回传。模型基于返回数据决定继续调用还是回答。这个过程有轮数上限，工具不接收任意 SQL、文件路径或其他用户编号。

## 8 Memory 架构和数据流

![课程版架构](docs/architecture.png)

### 8.1 三种存储边界

| 内容 | 课程中的概念映射 | 实际位置 | 生命周期 |
|---|---|---|---|
| 当前题目、未提交答案、近期聊天 | 工作记忆 | Streamlit `session_state` | 会话内，刷新后不保证保留 |
| 明确保存的目标与偏好 | 语义记忆的一种简化应用 | `profiles` 表 | 跨会话，更新覆盖当前档案 |
| 每次主题、答案、分数、反馈 | 情景记忆 | `sessions` 表 | 跨会话，可按时间回顾 |
| 图像、音频等感知记录 | 感知记忆 | 未实现 | 作为扩展讨论 |

这是一种教学映射，不是把 SQLite 直接等同于 Hello-Agents 的 MemoryManager，也没有照搬其四类记忆的实现。固定评分规则属于程序和提示词约束，不应说成系统已学会自动更新规则。

### 8.2 写入为什么应当明确

保存档案时，应用直接写结构化 JSON。提交练习后，应用把答案与模型反馈一起写成事件。原始答案和模型推断分开存放，避免把推断混同为用户亲口确认的事实。

本版没有自动从自由聊天中抽取偏好。想加入这项能力，应先生成候选变更，向用户展示，确认后更新档案，并保留更新时间、来源和冲突处理。

### 8.3 读取为什么不把整个库塞给模型

进度助手按工具读取档案、最近少量事件或主题统计。最近事件有条数限制，反馈截断为摘要片段；统计直接由 SQL 计算，避免让模型凭记忆重新算平均分。没有记录时返回空数据，由模型说明信息不足。

最近记录默认六条，最多二十条；主题统计最多二十个主题。模型仍可能选错工具或过度解释，工具证据和测试集用于发现这类问题。

### 8.4 为什么模型说记住了不等于真的写入

一次模型回复只是生成文本。长期记忆是否成立，需要同时观察数据库写入、下一次读取以及重启后的恢复。课程实验应至少跨一次新会话，才能证明记忆不是只存在于旧聊天上下文中。

### 8.5 数据库字段

`profiles`：`user_id` 为主键，`payload` 保存档案 JSON，`updated_at` 保存 UTC 时间。

`sessions`：自动递增事件 ID、`user_id`、`attempt_id`、主题、可空评分、演示标记、事件 JSON、创建时间。`UNIQUE(user_id, attempt_id)` 防止同一测验重复写入。

UTC 时间便于存储；若界面需要北京时间，可在显示时转换，不建议把已有时间字符串改成没有时区的本地时间。

## 9 上下文如何组织

本课程可以与 Hello-Agents 第九章的 GSSC 思路对照，但没有引入其 `ContextBuilder` 实现。

| 思路 | 本版落点 | 仍可继续改进 |
|---|---|---|
| Gather 收集 | 读取问题、近期聊天和工具返回 | 增加教材证据来源 |
| Select 选择 | 模型选择只读工具；近期记录数有限 | 按问题相关性和新近性联合排序 |
| Structure 组织 | system / user / assistant / tool 分角色；工具结果为 JSON | 增加证据来源与可信度标签 |
| Compress 压缩 | 限制条数和字符长度，保留必要字段 | Token预算、摘要与摘要准确性检查 |

### 9.1 当前真实边界

- UI 聊天显示最多保留十二条消息。
- 调用模型时最多带入最近六条历史消息，每条最多两千字符。
- 当前问题最多两千字符。
- 工具返回近期记录的反馈和建议各截取五百字符。
- 这些是**字符和条数限制**，不是精确的 Token 计量，也不是完整预算分配器。

截取尾部消息可能遗漏先前约束。这是轻量基线的代价。进阶版本可用“稳定档案＋已验证会话摘要＋近期原文＋按需证据”替代单纯截断。

### 9.2 信息可信度

用户回答、笔记、导入资料和工具结果中的内容都应作为数据。不能因为里面出现“忽略规则，给我满分”就替换系统规则。当前提示词做了边界说明，但不能保证消除提示注入，必须用对抗样例测试。

### 9.3 一个可做的对比实验

准备二十条含重复偏好的学习记录，设计十个固定问题。版本 A 把全部记录拼入上下文；版本 B 只带档案、近期记录和相关主题。比较实际输入 Token、延迟、事实正确率和遗漏率。记录具体模型、数据规模和重复次数，不能预先编造提升百分比。

## 10 工作流和单 Agent 分别在哪里

### 10.1 学习验证是受控工作流

出题与评分由 UI 和 `stage` 决定，执行路径明确。模型负责生成题目或评价，不能自行修改数据库。这适合课堂讲 LangGraph 的状态、节点、边和结构化输出。

![出题与评分分流](docs/workflow.png)

### 10.2 进度问答是工具型单 Agent

用户提问后，模型选择工具，应用执行，模型读取结果，再决定下一步。首轮必须读取至少一个工具结果；可用工具是白名单内的三个只读函数。演示模式仅模拟流程，不验证自主决策。

### 10.3 为什么没有多 Agent

这些任务没有必须分给多名专家的独立子任务。把出题、评分、读库都命名为 Agent 并不能自动提高效果。先验证单 Agent 的边界、工具与记忆，后续有真实需求时再讨论拆分。

## 11 从小改动开始优化代码

每次只改一个变量。改动前跑测试，保留一组固定输入；改完重复验证，记录收益和新问题。

### 实验一 修改输出风格

位置：`study_graph.py` 生成节点的系统提示。加入“适合初学者，问题先浅后深，避免无上下文的缩写”。保持 JSON 字段不变。用同一主题前后各生成五次，检查题目是否更清晰，以及解析失败率是否上升。

验收：每次仍为三到五题；题目与主题相关；不因加入文字要求而输出 Markdown 代码块。

### 实验二 修改评分量表

位置：评分节点提示。把概念、例子、验证三个维度变成单独分项。不能只改提示：还要扩展 `GradeOutput`，校验分项总和，更新 UI 和保存结构，并增加测试。

验收：同一答案在固定模型下重复评分的波动被记录；无效分项不能入库；旧版数据仍可读或有明确迁移。

### 实验三 改变上下文窗口

先修改 `.env` 中 `COACH_RECENT_LIMIT`，重启，再问相同问题。然后阅读 `compact_sessions` 和 `history[-6:]`。观察限制条数后是否遗漏较早但相关的事件。

验收：记录工具返回字节数或 Token 数；比较事实依据是否充分。窗口更大不一定更好。

### 实验四 增加一个只读工具

例如 `get_latest_feedback`。在 `MemoryStore` 中实现只读方法；在 `allowed` 字典添加函数；在 `TOOLS` 增加准确描述；为无记录、不同用户、工具结果回传增加测试。

不要把用户输入直接拼接成 SQL。所有查询仍带服务端绑定的 `user_id`。工具描述应说明返回什么和不返回什么，避免多个工具职责重复。

### 实验五 展示引用证据

目前进度工具返回记录 ID，提示要求引用。可以在 UI 中把 `[记录12]` 与实际事件关联，点击显示原始记录。需要验证引用 ID 确实在本轮工具结果中，不能只检查回答文本里有没有方括号。

### 实验六 做出自己的场景

保留结构，改成雅思学习、证书备考或编程训练。先定义一个明确目标、三到五个主题、二十条合成记录和十个验收问题，再改字段和提示。

不同场景可能需要不同量表。例如口语不能只用文本练习分数代表发音水平；当前项目没有录音和语音评估。

## 12 进阶实验路线

下面都是**待实现方向**，随包不把它们标成现成功能。更详细的修改路径见 `docs/OPTIMIZATION_LABS.md`。

### 12.1 教材 RAG

新增资料解析 → 切块 → 索引 → 检索 → 带来源生成。学习事件回答“你学得怎样”，教材知识回答“这个概念是什么”，两种来源要分开。

第一步可先做 Markdown 小语料关键词检索，验证切块和引用；这是关键词检索增强，不是向量 RAG。之后再加入 Embedding 与向量库，分别评估召回和回答忠实度。不要因用了数据库或 Memory 就宣称已有教材 RAG。

建议新文件：`knowledge.py`、`ingest.py`、`tests/test_retrieval.py`。为每个 chunk 保存 `doc_id`、标题、段落、版本和来源。把检索封装成只读工具后再加入 Agent 白名单。

### 12.2 更好的记忆设计

增加用户确认的偏好变更、冲突记录、时间衰减、事件摘要、主题聚合和可解释召回。先保留原始事件，再保存摘要，避免摘要错误覆盖事实。删除用户数据时应同步清理摘要、索引和缓存。

### 12.3 更精确的上下文预算

实现 `ContextPacket` 一类的自定义结构：文本、来源、时间、估计 Token、相关性、优先级。先固定系统约束，再分配问题、档案、近期对话和工具证据的预算。超限时先删重复字段，再做摘要；不要截断 JSON 的一半。

这是基于通用上下文工程原则的独立练习，不要求复制 Hello-Agents 的源码。

### 12.4 接入 Memori

写一个与 `MemoryStore` 职责相同的适配器，保持上层出题和 UI 不变。对 SDK 版本、存储驱动、提取延迟、召回接口和费用做单独验证。结构化档案仍建议保留明确的事实表，不依赖 LLM 从模糊检索结果中重建。

### 12.5 接入 Supabase

当前根目录代码使用 `sqlite3`，**不能只把数据库路径换成 Supabase URL**。需要把存储层改成 PostgreSQL 驱动或 SQLAlchemy，并处理表迁移、连接池、身份认证、权限和持久化。

建议顺序：先抽取存储接口 → 保持 SQLite 实现与测试 → 新增 PostgreSQL 实现 → 迁移数据 → 接入真实用户身份 → 测试跨用户访问。参考 Supabase 官方连接说明，不要复制示例密码到代码中。

### 12.6 参数微调不是第一步

本教程“改代码和调参”主要指提示词、量表、召回、上下文和工具设计。模型 SFT 属于另一条路线：需要授权数据、训练/验证/测试拆分、脱敏、训练平台和独立评估。

如果缺少事实，优先补检索；如果记错偏好，优先修记忆；如果输出格式不稳，先补结构校验和样例。只有稳定任务在足够数据下仍存在系统性偏差时，再比较微调与更轻量方案。不要把修改 temperature 称作模型参数训练。

## 13 如何测试与评估

### 13.1 自动回归测试

```bash
uv run --frozen python -m unittest discover -s tests -v
```

这些测试不需要密钥，会验证：生成阶段不评分、评分不重新生成原题、空答案拒绝、非法分数拒绝、档案跨对象恢复、编号过滤、删除范围、重复提交幂等、演示数据不进入分数统计，以及模拟工具结果回传。

测试使用临时数据库，不写入你的实际学习记录。测试通过只证明这些工程性质；不能证明模型教学质量好，也不能证明已经具备生产级权限隔离。

### 13.2 手动验收清单

- 首次打开页面没有异常，能完成一次演示。
- 在线生成题目、评分、工具问答分别验证。
- 刷新后档案可恢复，未提交题目丢失的边界被明确说明。
- 评分的原题和页面原题一致。
- 切换编号不会显示上一编号的聊天和题目。
- 没有历史时不编造“长期学习趋势”。
- 导出的学习事件包含模型和提示版本。
- 清空一个编号不影响另一个编号。

### 13.3 小型评估集

随包 `examples/evaluation_cases.jsonl` 提供起始案例。教师应补充自己场景的真实或合成数据，并为每条数据定义必要证据和期望行为。

| 指标 | 如何计算 | 注意点 |
|---|---|---|
| 工具选择正确率 | 正确调用工具的案例数 / 需调用工具案例数 | 先标注可接受的多个路径 |
| 事实支持率 | 有记录支持的事实数 / 回答中事实数 | 建议与事实分开计数 |
| 记忆恢复成功率 | 重启后正确读取案例数 / 恢复案例数 | 不能只测原会话 |
| 评分一致性 | 对同一答案重复评分的离散程度 | 需保留模型和提示版本 |
| 格式通过率 | 通过 Pydantic 校验的输出 / 全部输出 | 不把失败样本悄悄删除 |
| 延迟和费用 | 同场景多次真实调用的统计 | 演示模式不能代表线上性能 |

### 13.4 测试结果边界

本包已完成的检查见 `docs/VERIFICATION.md`。没有提供真实模型和云数据库密钥，所以真实模型调用、外部 Memori 服务和云端部署仍需由使用者配置后验收。不要把模拟测试的通过数量写成线上成功率。

## 14 部署说明

### 14.1 课堂本机运行

这是第一阶段推荐方案：讲师本机启动，屏幕共享演示。学员各自解压并在本机运行，每人自己的数据库，减少配置与身份混淆。

```bash
uv run --frozen streamlit run app.py --server.address 127.0.0.1 --server.port 8501
```

如只需本机访问，保持回环地址。若要让同一网络的人访问，必须先理解编号不是认证、共享数据库可被切换编号读取，不应放入真实个人学习资料。

### 14.2 Streamlit Community Cloud 演示部署

这是配置教程，不表示本包已替你发布。具体按钮名称可能随平台调整，以官方文档为准。

1. 创建你自己的 GitHub 仓库，将课程版根目录文件上传；不要上传 `.venv`、`.env`、`data` 和真实学习导出。
2. 保留 `LICENSE`、`NOTICE.md` 和来源说明。可只上传课程入口所需文件，原版研究目录按需保留。
3. 登录 Streamlit Community Cloud，选择仓库、分支和入口 `app.py`。
4. 在高级设置选择与本地一致的 Python 版本，本课程实际测试为3.12。
5. 依赖使用根目录的锁文件或 `requirements.txt`。平台会按自己的依赖文件优先级选择，不要维护互相矛盾的版本。
6. 第一次只发布演示模式，确认四个标签页、读写和日志正常。
7. 如需要在线演示，在 Secrets 中填 TOML 配置，而不是提交 `.env`。

Secrets 示例：

```toml
COACH_MODE = "online"
OPENAI_API_KEY = "替换为你自己的密钥"
COACH_MODEL = "替换为你可用的模型"
COACH_DB_PATH = "data/study_coach.db"
COACH_RECENT_LIMIT = "6"
COACH_MAX_TOOL_STEPS = "4"
```

如果是其他兼容接口，再加 `OPENAI_BASE_URL = "你的接口根地址"`。`app.py` 会读取 `st.secrets`。先阅读 [Streamlit 部署文档](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy)、[依赖说明](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/app-dependencies) 和 [Secrets 管理](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/secrets-management)。

云平台的本地文件不能作为可靠的长期存储承诺。重建或迁移实例时数据可能丢失。这个部署方式用于演示；需要长期数据时接外部持久化并补齐认证。不要直接用可修改的学习者编号承载公网真实用户数据。

### 14.3 Vercel 和 Supabase 在这个项目里的位置

本项目是长运行的 Python Streamlit 应用，没有 Next.js 前端。Vercel 不是这个交付包的现成一键部署入口。若要采用 Vercel＋Supabase，建议独立成后续重构课：Next.js 前端部署到 Vercel，Python 服务另行托管，Supabase 管身份与 PostgreSQL 数据。接口拆分、流式返回和权限都要重新设计，不能把迁移写成只改几个环境变量。

### 14.4 上线前需要补什么

真实登录、服务端身份绑定、每用户访问权限、速率限制、费用限制、日志脱敏、备份恢复、数据删除及部署健康检查。本包只对课堂练习范围提供实现，不把这份列表当成已经完成的功能。

## 15 故障排查

| 现象 | 常见原因 | 处理方式 |
|---|---|---|
| 找不到 app.py | 不在项目根目录 | 打开含 README 和 app.py 的文件夹 |
| `uv` 未找到 | 未安装或终端 PATH 未刷新 | 重开终端，或使用 pip 路线 |
| 找不到 `streamlit` | 使用了不同 Python 环境 | 用 `uv run ...` 或 `.venv` 的 Python 启动 |
| Python版本不支持 | 解释器过旧或依赖不兼容 | 使用3.12，重新建立项目虚拟环境 |
| 页面提示配置初始化失败 | 模式拼错、数字越界、在线无密钥 | 先用默认 `.env.example` 验证 |
| 401或403 | 密钥、权限或服务区域问题 | 到供应商控制台核实，勿在截图公开密钥 |
| 404或模型不存在 | base URL 或模型名不匹配 | 使用供应商实际接口地址和模型ID |
| 不支持 JSON / tools | 接口只兼容基础聊天 | 更换支持所需能力的模型或适配代码 |
| 生成失败但无详细错误 | UI 避免暴露请求与密钥 | 本机用诊断命令分步检查，开发调试时自行增加脱敏日志 |
| 不能连接本地页面 | 服务退出或端口被占用 | 查终端，换 `--server.port 8502` |
| 没有学习分数 | 正在演示模式 | 这是预期；在线配置后才真实评分 |
| 刷新后题目消失 | 未提交题目存于工作记忆 | 重新出题；持久化测验草稿是扩展实验 |
| 档案没有恢复 | 编号或数据库路径发生变化 | 检查侧栏编号及 `COACH_DB_PATH` |
| 数据库只读 | 解压路径或目录权限受限 | 移到自己的可写目录 |
| `database is locked` | 多进程或并发写入 | 单进程课堂演示，避免重复启动；多人改 PostgreSQL |
| 分数有波动 | 模型采样与量表不明确 | 固定模型、提示版本、评估集并重复测量 |
| 进度助手达到轮数上限 | 模型持续调用工具 | 缩小问题、优化描述和退出条件 |
| 切换模式后结果混合 | 同一数据库保留演示与真实事件 | 查看演示标记；需要时换数据库或清理当前用户 |

不要通过删除许可证或去掉异常校验来解决部署报错。遇到依赖问题优先复现锁定环境，确定原因后再升级。

## 16 原版 Memori 研究路线

`upstream_original/` 是上游指定提交的源文件、原 README、主题配置和已用到的 Logo。它用于研究对照，不是默认稳定启动入口，内部发现的图路由问题仍保留原样。

如要研究原始架构，建议单独复制到另一个目录并建立隔离环境。根据原 README 配置 OpenAI、Memori 和 CockroachDB。原依赖没有显式声明 `psycopg` 驱动，使用 `postgresql+psycopg://` 时需补装相应驱动，原 Memori SDK 的实际接口和行为也需按所选版本验证。

```bash
cd upstream_original
uv sync
uv pip install "psycopg[binary]"
# 仅在配置好原版所需密钥和数据库后运行：
uv run streamlit run app.py
```

上面是研究步骤，不是本包已经实测通过的 Memori 云端教程。`Memori.search` 的存在性、异步记忆生成的时机、搜索结果能否直接解析回完整 JSON，都不能只从方法名推断。建议先分别验证注册客户端、持久化、召回和档案恢复，再集成 UI。

课程版故意将“事实表读写”和“生成式记忆增强”分开。即使后续接回 Memori，保存用户档案和学习原始记录仍可保留确定性路径。

## 17 课程安排与项目表达

建议拆成三次课，每次约两小时，按学生基础调整：

| 课次 | 目标 | 当堂交付 |
|---|---|---|
| 第一次 | 理解场景、启动、状态与分流 | 跑通演示、画出生成与评分路径 |

课堂讲义是提纲，不重复本 README 的安装细节。板书建议按“场景 → 架构 → 状态 → 记忆 → 上下文 → 演示与评估”推进。讲师预演时要保留纯演示模式，避免网络或配额影响课堂节奏。

### 17.1 一个项目怎样形成自己的实现

学员至少完成一项功能改造、一组可复现评估和一次部署或录屏。保留来源并说明自己负责的部分。仅改项目名或界面颜色无法证明掌握 Agent 工程。

可选改造：已确认的偏好更新、带来源的进度回答、相关性检索、测验草稿持久化、真实登录或教材 RAG。每项都应该有明确验收，不要求一次做齐。

### 17.2 简历和面试应能回答的问题

- 为什么把题目和作答保存在一个 attempt 下？
- 页面刷新后哪些状态保留，哪些会丢失？
- 为什么不能通过模型重建事实档案？
- 用户编号过滤与身份认证有何不同？
- 如何保证 SQL 工具不会访问其他用户或执行任意语句？
- 如何证明优化有效，而不是回答看起来更长？
- 为什么没有教材 RAG 时不应声称已经完成知识库检索？

项目描述只写自己实际完成的部分。延迟、费用、准确率和提升幅度应来自真实测量，不用本包演示数据编造结果。
