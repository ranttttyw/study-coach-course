# 学习教练优化实验手册

本手册是可选作业，不是已实现功能清单。每项实验按“问题—改哪儿—验收—复盘”完成。先保留基线和固定输入，再改代码。

## 实验一 建立可检查的评分量表

**问题**：单一模型分数难以解释，重复评分可能波动。

**修改位置**：`study_graph.py` 中 `GradeOutput`、评分节点提示，以及 `app.py` 结果展示。

1. 在 `GradeOutput` 加入三个分项：概念0到40，例子0到30，验证0到30。
2. 用 Pydantic 的 model validator 检查总分等于分项之和。不要只在提示里要求总分一致。
3. 保留 `feedback` 和下一步建议。在线总分不能为 null，演示版分数仍应为空。
4. 修改保存结构，给新版本标记 `prompt_version` 与 `schema_version`。
5. UI 展示分项，并保留旧版记录的读取兼容。先判断字段存在，不直接按新字段读取全部旧事件。

**验收**：同一份题目与答案运行五次；统计均值和波动；至少准备一条总分不一致的假模型输出，验证系统拒绝。不能把文字变长当成评分改进。

## 实验二 让记忆支持更新与冲突

**问题**：当前档案是用户表单确认的最新值，没有历史版本和变更来源。

**修改位置**：`memory_utils.py` 增加 `profile_changes` 表；`app.py` 增加候选变更确认。

1. 用户说“我现在更喜欢练习题”，让模型提取候选字段和值。
2. 先显示旧值、新值、原话和变更时间；未确认前不更新当前档案。
3. 用户确认后在同一数据库事务内更新档案并追加变更事件。
4. 区分用户明确陈述、模型推断、系统默认值。不要让推断覆盖已确认事实。
5. 加入按用户删除时清理候选与历史的测试。

**验收**：旧偏好能被新偏好覆盖；取消确认不写入；其他用户看不到候选；变更来源可追踪。

## 实验三 从近期记录走向相关性召回

**问题**：最近六条记录可能漏掉两周前非常相关的一次学习。

**修改位置**：在 `MemoryStore` 新增 `search_sessions(topic, limit)`；在 `coach_agent.py` 增加搜索工具。

第一阶段可用固定主题过滤，先验证排序和来源。第二阶段尝试 SQLite FTS 或独立关键词索引。第三阶段再比较向量相似度与时间权重。

引入工具参数后，需要 JSON Schema、长度上限、Python端校验和参数化查询。工具中的用户身份仍从服务端绑定，不让模型传 `user_id`。主题变量通过占位符传入 SQL，禁止字符串拼接 SQL。

**验收**：构造“最近记录无关、较早记录相关”的案例；相关证据应进入返回结果，跨用户数据不能进入。分别报告 Recall@k 和最后回答的事实支持情况。

## 实验四 完成可控的上下文预算

**问题**：字符截断不能精确约束 Token，也可能截掉关键事实。

**修改位置**：新增 `context_builder.py`；将 `answer_progress` 中的历史和工具结果整理迁入该模块。

建议结构是独立练习，不复制外部教材代码：

```python
from dataclasses import dataclass

@dataclass
class Evidence:
    text: str
    source_id: str
    priority: int
    updated_at: str
    estimated_tokens: int
```

1. 收集系统约束、当前问题、档案、近期对话和相关事件。
2. 按信息用途划分预算；系统约束优先，不随意截断。
3. 用目标模型对应的计量方式估计 Token；未知模型记录估计误差。
4. 对事件去重，保留原始记录ID。超过预算时先删低优先级字段，再做摘要。
5. 摘要不能捏造来源；写入摘要后保留其覆盖的事件ID和版本。

**验收**：长问题、长档案和多工具结果下不超预算；关键约束仍保留；记录截断或摘要是否造成答案遗漏。输出必须是合法完整消息，不能切断JSON字符串。

## 实验五 增加教材知识检索

**问题**：当前系统知道“学了什么”，却没有可靠教材来回答“概念是什么”。

**新增模块**：`ingest.py`、`knowledge.py`、检索工具和评估集。

1. 使用自写或已授权的小型 Markdown 教材，不直接打包受非商业许可限制的教材内容。
2. 按标题和段落切块，保留文档版本、标题、段落、来源链接。
3. 先用关键词检索实现最小证据链，再按需要引入 Embedding。
4. 将“用户学习历史”和“通用教材知识”作为不同工具，避免混在一个索引里丢失身份边界。
5. 回答附带真实命中的片段ID；检索无命中时允许拒答。
6. 删除或更新文档时同步失效旧索引。

**验收**：准备至少二十个教材可回答问题、五个无答案问题和五个干扰问题。分别评估召回、引用是否存在、回答是否被证据支持。

只实现关键词检索时，应称为关键词检索增强，不能宣称已经完成向量检索或重排序。

## 实验六 持久化测验草稿

**问题**：未提交题目保存在 Streamlit 会话，刷新可能丢失。

**修改位置**：新增 `attempts` 表；UI 从数据库恢复当前未完成测验。

保存题目编号、用户ID、档案快照、日志快照、题目、生成模型、状态和创建时间。状态建议为 draft、submitted、graded。评分操作先校验题目归属和状态，再处理。多人并发时使用事务和唯一约束，防止重复评分或串题。

**验收**：出题后关闭浏览器再打开，题目不变；其他用户不能读取草稿；已评分测验再次提交不会写入第二条有效结果。明确“防重复写库”和“防重复调用模型”是两个不同问题。

## 实验七 从 SQLite 迁移到 PostgreSQL

**问题**：本地教学数据库不适合多实例持久化。

先为存储层写接口和共同契约测试，保留 SQLite 作为本地实现，再用 SQLAlchemy 或 PostgreSQL 驱动新增实现。`sqlite3` 的占位符、表定义与冲突语法不能不加核对地照搬。

连接 Supabase 时读取官方 Connect 面板中的实际地址、用户和端口，配置 SSL；确定使用直连还是连接池，检查驱动对预处理语句的要求。不要把数据库服务端凭据放进前端。

加入身份认证之后，用户ID来自已验证的服务端身份，不再来自可编辑输入框。若直接使用受服务角色授权的数据库连接，不能只假设 RLS 会替你完成全部用户隔离，应用查询仍需严格绑定身份与最小权限。

**验收**：备份与恢复、跨用户访问、断线重连、迁移回滚、并发写入、删号清理。只在测试库演练，不对真实用户库直接执行破坏性脚本。

## 实验八 什么时候考虑模型微调

先用评估集定位问题：事实缺失应补检索，身份错误应修权限，评分漂移应改量表与校准，输出不合法应做结构验证。

如果有足够的已授权、质量稳定的样本，且提示与检索优化后仍存在固定任务偏差，可比较SFT。按学习者或数据来源划分训练和测试，避免同一人的近似答案同时进入两边。保留原始基线，测量格式通过、任务效果、幻觉、成本与延迟。训练数据应去除密钥、个人资料和无授权教材。

本包没有训练脚本或微调模型，不提供未验证的训练成功率。
